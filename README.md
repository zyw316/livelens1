# LiveLens · AI 直播弹幕洞察助手（黑客松 Demo）

> 面向**服装直播商家**，把直播间弹幕实时转化为可执行的需求洞察。
>
> 默认使用**本地模拟演示数据**（界面标注「演示数据」）；切换数据源到 **「保利威直播聊天室（真实弹幕）」** 后，接入保利威官方 Web 观看页 SDK 接收频道 `8620440` 的真实观众消息。

## 一、启动方式

Demo 是**零构建步骤**的静态站点（原生 ES Module + 原生 CSS/JS，无框架、无打包器）。
因为使用了 ES Module，**必须通过 HTTP 服务打开**（直接双击 `index.html` 走 `file://` 协议会被浏览器 CORS 策略拦截）。

任选一种：

```bash
# 方式 1：Node 本地服务（含 AI 洞察接口，推荐）
cd livelens-demo
npm run dev                     # 等价于 node server/index.mjs
# 打开 http://127.0.0.1:4173

# 方式 2：纯静态（AI 面板自动走本地规则模拟，其余功能完全一致）
python -m http.server 4173      # 打开 http://127.0.0.1:4173
npx --yes serve -l 4173 .       # 或 npm start
```

启动后浏览器访问 <http://127.0.0.1:4173>。

> **AI 面板三级降级**：`npm run dev` 启动时走后端通道（可配真实模型）；纯静态托管
> （GitHub Pages / Vercel 静态 / `python -m http.server`）下云端与后端都不可用，
> 前端自动落到第三级「本地规则模拟」，面板照常有洞察（标注「模拟输出」+ 原因），
> 弹幕筛选 / 分类 / 聚合 / 告警不受任何影响。

核心逻辑不依赖浏览器，可以随时跑命令行冒烟测试（零依赖）：

```bash
node tools/smoke-test.mjs
```

## 三、统一数据格式与对外接口

### 统一弹幕格式（`DanmakuMessage`）

所有弹幕源必须先经 `normalizeMessage()` 转成此结构：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 全局唯一 |
| `roomId` | string | 房间 / 频道号 |
| `userId` | string | 用户标识（仅用于同人去重） |
| `userKey` | string | 脱敏展示标识，如 `观众#a3f1` |
| `text` | string | 原始文本 |
| `normalizedText` | string | 归一化文本（去表情/标点，保留 `?` 与数字） |
| `timestamp` | number | 毫秒时间戳 |
| `source` | `'mock' \| 'polyv'` | 数据来源 |
| `meta` | object | 源原始字段（不参与算法） |

## 五、算法说明

### 1. 去噪（6 类规则，按判定成本排序）

| 原因 | 规则 | 受敏感度影响 |
| --- | --- | --- |
| 纯表情/符号 | 归一化后为空但原文非空；或 `[呲牙][大笑]` 这类方括号表情剥掉后无实质内容 | 否 |
| 内容过短 | 归一化长度 < 阈值 | 是（2/3/4 字） |
| 重复字符刷屏 | 单字重复 ≥3 或最大连续重复超阈值且字符丰富度 <0.4；同一方括号表情连刷 ≥3 | 是 |
| 广告/营销话术 | 正则词库（加微信/签到/抢红包/纯数字…） | 否 |
| 短时间重复弹幕 | 同一观众窗口内重复发送同一句 → 过滤；**全局雷同则区分「少数人刷屏」与「多人真实同问」**：只有 ≤2 人快速复读或窗口内同文 ≥8 次才过滤 | 是（窗口 8/15/25s） |
| 无实质信息 | 寒暄短语词库 | 是（≥45 才启用） |

### 2. 意图 / 分类 / 严重度

- **意图**：疑问词 / 购买词 / 反馈词三组词典投票，裁决优先级 `提问 > 反馈 > 购买 > 闲聊`。
- **分类**：11 个服装行业类目 × 加权关键词词典，取最高分类；置信度 = 类别优势度 ×0.7 + 绝对得分 ×0.3。
- **严重度**：质量安全（过敏/甲醛/起球…）> 履约售后（少发/假货/投诉…）> 直播间阻塞 > 转化阻塞；多条命中时取最大值 + 其余按 `0.25/i` 衰减累加，避免堆叠刷分。

### 3. 重复问题聚合

- 只对通过去噪、且意图为提问/购买/反馈的弹幕聚簇（闲聊不参与）。
- 相似度 = `max(Jaccard, Containment × 0.85)`，计算前先剔除口语填充词（`这个/主播/的/了/吗/呀…`），显著提升「这个针织衫有哪些尺码呀」≈「针织衫有什么尺码」的匹配率。
- 默认阈值 **0.45** 是照着演示语料调出来的，可用滑块实时验证。

### 4. 重要低频问题（核心差异化）

不看出现次数，看「**单位出现次数的危害度**」：

```
priority = severity × 0.65 + rarity × 0.25 + recency × 0.10
rarity   = count ≤ 1 ? 1 : 1 - (count-1)/lowFrequencyMax × 0.6
recency  = 1 - 距今毫秒 / 5分钟
```

只有 `severity ≥ 0.5` 且 `count ≤ 3` 才进告警列表 —— 高频问题走常规统计，不占用主播注意力。
演示语料里「起球 / 掉色 / 少发 / 皮肤过敏 / 虚假发货」这类伤害大但只出现一两次的问题会被优先置顶。

### 5. 商家关注榜（核心差异化：频率 × 语义 × 紧急度）

不按频率简单排名，而是回答「**此刻最值得商家关注的问题是什么**」：

```
综合关注分 = 频率 × 0.35 + 语义 × 0.25 + 紧急度 × 0.40
频率   = min(1, count / 8)          // 20 人问尺码 → 拉满
语义   = 是否下单决策关键点           // 尺码/面料/价格/售后/支付=1，直播间体验=0.3
紧急度 = 异常命中 ? 1 : 严重度        // 支付失败这类异常永远排最前
```

每个上榜问题带一个**类型标签**，对应四种典型情形：

| 类型 | 情形 | 判定规则 |
| --- | --- | --- |
| 异常待核查 | 1 个人反馈支付失败 | **双信号规则**：同时命中交易行为词（支付/下单/扣款…）+ 失败异常词（失败/付不了/不到账…）。刻意保守——单句负面评价（如「太贵了」）不会被误判为故障 |
| 低频高危 | 1~2 个人说起球/过敏 | 复用第 4 节的低频告警结果 |
| 高频需求 | 20 人问尺码 | 量大且属事实性需求（尺码/库存/物流），商家可直接行动 |
| 购买顾虑 | 12 人问面料闷不闷 | 主观性顾虑（面料/洗护/颜色），需主播解释打消 |
| 集中投诉 | 多人反馈同一不满 | 量大 + 反馈意图 |

榜单每条都展示**分数构成**（频率/语义/紧急度各占多少），评审时可以讲清楚每一分是怎么来的。
点击榜单项会联动「重复问题聚合」选中并高亮弹幕流中的对应弹幕。

## 六、保利威接入（已实现，可端到端验证）

已接入官方 Web 观看页 SDK `@polyv/live-watch-sdk@2.20.0` 的**聊天室模块**，
监听官方 `ChatEvents.ChatMessage` 事件；不自建 WebSocket、不伪造 SDK 调用。
SDK 用官方 ESM 产物 + 浏览器原生动态 `import()` 加载，**无需任何构建工具**。

```
聊天室 →(SDK 内部 socket)→ ChatEvents.ChatMessage
       → polyvProvider.mapChatMsg() → normalizeMessage() → store → 现有分析流程
```

配置在 `src/config.js`：测试频道 `channelId: '8620440'`、AppId `gq7s700644`、
`enabled: true`、`signEndpoint: ''`（该频道为无条件观看，前端不涉及任何密钥）。

### 用手机亲自验证（推荐）

保利威**不会把自己发的消息回播给自己**，所以必须「一端发、另一端收」——手机发最省事：

## 七、AI 洞察（免费云端大模型优先，自动降级）

面板在右列顶部（**「AI 洞察」**，右上角标签显示当前模式：**真实模型** / **模拟输出**）。
AI 请求按优先级自动选择通道，**任何一级失败都自动落到下一级，页面永远有洞察可看**：

| 优先级 | 通道 | 条件 | 说明 |
| --- | --- | --- | --- |
| 1 | **WorkBuddy 云端大模型**（glm-5.3-flash 等） | 默认启用 | **免费、免密钥**：前端直调云服务 keyless LLM，无需注册任何模型厂商 |
| 2 | 自有后端 + DeepSeek 等 | 项目根 `.env` 配了 `AI_API_KEY` | OpenAI 兼容协议，服务端读密钥 |
| 3 | 本地规则模拟（前端） | 以上都不可用 | 不联网、不需要任何密钥，面板永远有洞察可看 |

> 云端通道只放行**应用自己的发布域名**与**本地调试**（服务端按 Origin 精确校验）。
> 把页面挂到别的域名（如 GitHub Pages）时云端会被拒，这是**预期行为**——会自动落到
> 第二级；后端也不在（纯静态托管 POST 返回 404/405）时落到第三级本地模拟。

### 1. 各通道怎么配

- **云端（默认，零配置）**：激活云服务后已内置（`CONFIG.ai.cloud`）。模型在
  `glm-5.3-flash / glm-5.3 / hy3 / auto` 中自动挑选，都不在列表时取第一个可用模型。
- **DeepSeek（可选，本地稳定）**：

```bash
cp .env.example .env      # 填入 AI_API_KEY 等
npm run dev               # 重启后生效
```

常用服务对照（都兼容 OpenAI 协议）：DeepSeek `api.deepseek.com` / 智谱
`open.bigmodel.cn` / Moonshot `api.moonshot.cn` / 阿里百炼
`dashscope.aliyuncs.com/compatible-mode` / OpenAI `api.openai.com`。

**安全约定**：云端 publishableKey 只是应用标识、不带权限，可安全出现在前端源码；
DeepSeek 等密钥只从服务端 `.env` 读取（已被 `.gitignore` 忽略），任何响应里都不含密钥。

### 2. 为什么是「旁挂式」

```
弹幕 ──▶ core/analysis.js ──▶ store.result ──┬──▶ 原有 7 个面板（不受任何影响）
                                             └──▶ ai/batcher.js ──▶ POST /api/ai/insight ──▶ 面板
```

- AI 只**读** `store` 的成品结果，**不重算、不回写**任何统计；
- `src/core/` 里没有任何文件 import `src/ai/`（冒烟测试会断言这一点）；
- 关掉面板上的「启用」开关只是停掉批次调度，原有筛查与分类的分行完全不变。

### 3. 送出去的是什么

不是全量原始弹幕，而是**结构化摘要**：本批次的分类计数、代表性问题标题（每条截断 40 字）、
关注榜 Top5、低频告警 Top5。**不含 userId、不含 nick、不含保利威原始报文**（有测试断言）。
模型被要求：所有数字必须引用输入、禁止编造；只负责解释、判断与建议（`server/ai/prompt.mjs`）。

### 4. 批次节奏

默认每 **15 秒**检查一次，且至少积累了 **3 条新弹幕**才发请求；也可以点「立即分析」跳过等待。
参数都在 `src/config.js` 的 `CONFIG.ai` 里（`batchIntervalMs` / `minNewMessages` / `timeoutMs`）。

### 5. 降级行为

| 情况 | 面板表现 | 核心功能 |
| --- | --- | --- |
| 纯静态托管打开（GitHub Pages 等，POST 返回 404/405） | 第三级本地规则模拟接管，洞察末尾注明「为什么是模拟」 | 完全正常 |
| 手动关闭 AI 开关 | 「AI 洞察已关闭…互不影响」 | 完全正常 |
| 后端返回结构不合法 | 提示失败原因，不渲染半截内容 | 完全正常 |
| 云端不可用（域名不在白名单 / CDN 不通 / 超时） | 自动回退自有后端；后端也不在则回退本地模拟 | 完全正常 |
| 真实模型调用失败（401 / 限流 / 网络 / 超时） | 自动回退本地模拟，洞察末尾注明原因 | 完全正常 |
| 模型输出不是合法 JSON | 自动带提醒重试一次，仍失败则回退 | 完全正常 |

### 5-1. 部署到 GitHub Pages（纯静态）时会发生什么

页面推到 GitHub Pages 后，AI 三条通道的状态与网站的应对：

| 通道 | 在 GitHub Pages 上的状态 | 网站行为 |
| --- | --- | --- |
| 云端大模型 | 域名不在平台 Origin 白名单，被拒（403） | 本次会话直接标记不可用，不再重试 |
| 自有后端 | 静态托管没有 Node 服务，POST 返回 405 | 识别为「后端不可用」，冷却 60 秒不刷屏 |
| 本地规则模拟 | 前端纯函数，随时可用 | **立即接管**，面板显示洞察 + 「模拟输出」标签 + 原因说明 |

想在 GitHub Pages 上也用**真实模型**，二选一：

1. **后端单独部署**（Render / Railway / 自己的服务器）：`node server/index.mjs` 起服务，
   配好 `.env` 里的 `AI_API_KEY`，再用 `CORS_ALLOWED_ORIGINS=https://你的用户名.github.io`
   放行页面域名（服务端已支持 CORS 与 OPTIONS 预检）；前端把 `CONFIG.ai.endpoint`
   指向后端地址即可。
2. **换支持后端的托管**：直接部署整个仓库（WorkBuddy 发布、Render 等），
   页面与后端同域，零额外配置。

### 6. 服务端与云端通道结构

```
src/ai/
  prompt.js            系统人设 + 输出契约（云端与服务端共用同一份）
  cloudClient.js       前端直调云端 LLM：CDN 动态加载官方 SDK → 选模型 → 流式收集
  batcher.js           通道编排：云端优先 → 失败回退自有后端 → 后端不可用回退本地模拟
  mockInsight.js       本地规则模拟（第三级兜底，前端纯函数）
server/
  index.mjs            静态托管 + /api/ai/insight + /api/ai/health + CORS
  env.mjs              .env 加载、AI 配置与 CORS 白名单读取（AI_API_KEY / CORS_ALLOWED_ORIGINS）
  ai/
    prompt.mjs         Prompt 转发（真正文本在 src/ai/prompt.js）
    openaiCompat.mjs   OpenAI 兼容客户端（错误分类 + 超时）
    providers.mjs      编排：真实优先 → 失败自动回退本地模拟
```

- `npm run smoke` —— 核心算法 + AI 旁挂隔离 + 云端通道回退 + 三级降级兜底（91 项）；
- `npm run test:ai` —— 自有后端链路测试（10 项，假模型服务器，不需要真密钥）。
